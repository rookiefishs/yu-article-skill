# 写作硬规则

## 语气
- 直接
- 简洁
- 口语化
- 像真实的人在说话
- 带个人判断，但不要端着，不要说教
- 不要爆粗口，不要说脏话

## 结构
- 先讲结论，再讲原因，再讲例子或动作
- 一段只推进一个意思
- 段落过渡自然，不靠套话硬转场
- 少用副词和过渡词

## 正文文件限制
- `标题-正文.md` 默认用于直接复制使用
- 不要混入 Markdown 标记符号，如 `` ` ``、`*`、`>`
- 不要写代码块、引用块、无序列表标记
- 不要用 Markdown 粗体、斜体、行内代码包裹内容

## 谨慎使用的强化词
- `真的`
- `太`
- `非常`
- `特别`

这些词可以偶尔出现，但不要高频堆。
如果一段主要靠这些词抬语气，优先改成更具体的判断、场景、动作或后果。

## 必须多写的东西
- 真实场景
- 真实动作
- 真实问题
- 真实后果
- 能落地的判断标准
- 能马上执行的动作建议

## 明确不要出现的句式
- `为什么值得xxx`
- `有价值的地方是xxx`
- `不是xxx，而是xxx`
- `很多人以为xxx，其实xxx`
- `我现在越来越觉得xxx`
- `我这两天xxxx的时候，第一反应xx：xxxx`
- `xx真的xx`
- `这个项目真正值钱的地方`
- `真正xxx`
- `证明xxx`
- `值得xxx`
- `xx值得xx`
- `xx清楚xx`
- `xx更稳xx`
- `xx划算xx`

## 替代动作
- 直接说结论
- 直接说自己更认同什么
- 直接说更适合什么场景
- 直接说读者最容易卡在哪里
- 直接说先做什么，别急着做什么

## 不推荐写法
- 空泛讲大道理
- 一上来就下很大的判断，没有例子支撑
- 一段里塞太多观点
- 连续使用同一种句式
- 为了显得专业，故意写得很抽象
- 结尾写成感悟或抒情总结

## 自检清单
- 禁用句式是否出现
- 句子是否偏短
- 是否有具体例子支撑观点
- 是否有真实场景和动作
- 是否用了 `首先 / 其次 / 再次 / 然后 / 最后`
- 是否像在跟朋友解释一件事，而不是在写说明书
- 正文文件里是否混入 Markdown 装饰符号
- 封面提示词和配图提示词是否写混
