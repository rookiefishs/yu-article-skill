# 题型与内容组织方式

## 常见题型分布
- 工具清单型
- 问题诊断 / 解决型
- 新手入门 / 路径型
- 功能 / 项目介绍型
- 对比选择型
- 趋势 / 认知型
- 热点拆解 / 源码发现型

## 标题方向
- `为什么你用X总觉得Y`
- `X时，怎么解决和避免Y`
- `X和Y，我更推荐谁先用`
- `这个X能让你……`
- `我从X里提炼出N条……`
- `X竟然还能……`
- `不会用X没关系，……来了`

## 内容组织建议

### 工具清单型
适合：命令、工具、功能、习惯、规则清单。

写法：
- 标题直接点数量、对象、收益
- 开头别铺太大背景
- 每个点讲清作用、适用场景、解决什么问题
- 结尾直接收住

### 问题诊断 / 解决型
适合：不稳定、返工、出错、限制、混乱。

写法：
- 开头先点用户正在经历的问题
- 中间按原因 / 对应动作往下拆
- 多写止损动作和不这么做的后果
- 结尾收成一句明确建议

### 新手入门 / 路径型
适合：0 基础起步、怎么开始、流程怎么走。

写法：
- 先讲第一步最容易错在哪
- 再按流程往下拆
- 每一步都带具体例子
- 多写先做什么，别急着做什么

### 功能 / 项目介绍型
适合：新命令、新 Skill、新项目、新工作流。

写法：
- 先讲它是什么
- 再讲它能干什么
- 再讲适合谁、什么场景下用
- 有动作就按最小可用路径写

### 对比选择型
适合：两个工具、两条路径、先用谁。

写法：
- 先下明确判断
- 再解释这个判断适用于谁
- 再补另一边适合什么人
- 不写面面俱到的测评腔

### 趋势 / 认知型
适合：AI 变化、岗位变化、软件形态变化。

写法：
- 先给清晰判断
- 再用几个现实变化把判断撑住
- 避免大而空
- 让读者知道这件事和自己有什么关系

### 热点拆解 / 源码发现型
适合：源码泄露、隐藏功能、趣味发现。

写法：
- 开头抓事件或反差点
- 中间补证据和细节
- 别只写八卦，要写这件事说明了什么
- 有结论，但不要虚张声势

## 长文与图文的区别
- 长文更强调连续叙述和展开
- 图文更强调分点、节奏快、页面可拆
- 两者都要保持短句、真实场景、真实动作
