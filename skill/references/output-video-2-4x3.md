# 2号视频规范（4:3）

## 触发方式
用户明确说以下任意表达时使用本规范：
- `2号视频规范`
- `2号视频模板`
- `4:3视频模板`
- `用上次 superpowers 那种效果`

本规范不替换默认视频规范。用户没指定时，仍然使用原来的默认竖屏视频规范。

## 默认产物
- `素材文件/`
  - `DESIGN.md`
  - `标题-大纲.md`
  - `标题-配音文件.md`
- `素材/`
  - 原始网页截图、仓库截图、官网截图、效果录屏截图等
- `image/`
  - `1.png` 到 `N.png`
  - 用于视频工程的标准素材图
- `视频工程/`
  - 从 `assets/video-template-2-4x3/` 复制
- `标题.mp4`

## 画布
- 比例：4:3
- 分辨率：1440 x 1080
- FPS：24
- 默认时长：1 分钟左右，除非用户明确要求长视频，否则不超过 2 分钟

## 视觉方向
- 浅色科技图文风
- 主色：浅蓝、暖白、浅灰蓝
- 辅助色：少量浅紫，用作氛围光和进度条过渡
- 整体气质：干净、克制、工程感、流程说明感
- 不使用重霓虹、不使用深色全屏、不使用大面积紫色

## 页面布局
每页使用统一页面壳：
1. 浅色渐变背景
2. 大圆角主体卡片
3. 左侧：kicker、主标题、accent、流程点
4. 右侧：截图、网页、仓库页、规则文件或效果图
5. 底部：深色字幕条
6. 最底部：细进度条

默认主体卡片边距：72px。
截图容器使用 `object-fit: contain`，优先保证截图完整，不强行裁切重点内容。
截图容器背景必须是透明或浅色半透明，不能使用黑色、深色全屏底、深色留白或黑色渐变遮罩。
当截图比例和容器比例不一致时，留白区域应透出页面浅色背景，而不是填充黑色。

## 内容拆页
默认 5 到 7 页。
推荐结构：
1. 封面页：主题和核心判断
2. 问题页：用户遇到什么卡点
3. 规则页：这个 Skill 怎么介入
4. 流程页：具体工作链路
5. 场景页：适合什么任务
6. 结尾页：一句明确建议

每页只讲一个点。
每页要有不同的 caption。
标题尽量短，避免 4:3 横版里左侧文字拥挤。

## 素材规则
优先使用真实素材：
- GitHub 仓库截图
- skill 文件截图
- 官网或文档页截图
- 本地目录截图
- 效果前后对比截图
- 简短操作录屏截图

如果真实素材不足，可以补流程卡片、终端示意、目录结构示意。
素材先放入 `素材/`，再挑选复制到 `image/`，按 `1.png`、`2.png`、`3.png` 命名。

## 配音
默认使用小米 MiMo `冰糖` 音色。
配音稿控制在 300 到 500 个中文字符左右。
如果生成后音频超过默认时长，视频总时长跟随音频自动延长，不截断旁白。

## 动效
- 首屏直接在位，不空白开场
- 后续页面使用整页横向 slide / push 覆盖
- 页面内部只做轻微入场、缩放和截图浮动
- 不使用夸张旋转、强弹跳、复杂粒子

## 工程使用
当使用本规范时：
1. 从 `assets/video-template-2-4x3/` 复制到文章目录下的 `视频工程/`
2. 写入 `素材文件/DESIGN.md`
3. 写入 `素材文件/标题-大纲.md`
4. 写入 `素材文件/标题-配音文件.md`
5. 准备 `image/1.png` 到 `image/N.png`
6. 修改 `视频工程/build_hyperframes_video.py` 里的 `TITLE` 和 `SCENES`
7. 运行 `python build_hyperframes_video.py`
8. 先用 `PREVIEW_SECONDS=4 node render_with_puppeteer.js` 导出预览
9. 检查首帧、中间帧、字幕条、截图完整度
10. 再运行 `node render_with_puppeteer.js` 导出完整视频

## 验收清单
- [ ] 成片分辨率为 1440 x 1080
- [ ] 显示比例为 4:3
- [ ] 首帧不是空白背景
- [ ] 主体卡片边距统一
- [ ] 截图完整，没有裁掉关键信息
- [ ] 字幕条文字不溢出
- [ ] 转场是整页横向覆盖
- [ ] 音频没有被截断
- [ ] 成片输出在文章根目录
