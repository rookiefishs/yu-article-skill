# 视频生产流程规范

基于当前已验证的视频工程效果沉淀的标准流程。后续新视频默认按此流程制作。

## 整体流程

```
主题确定 → 内容拆页 → 配音文案 → 归档到素材文件 → 生成音频 → HTML排版 → 渲染视频到文章根目录
```

## 第一步：内容拆页（SCENES）

把内容拆成 5-8 个页面，每个页面对应一个场景。

### 页面类型

| 类型 | kind | 用途 | 是否显示配图 |
|------|------|------|:----------:|
| 封面页 | intro-cover | 标题、品牌、简介、内容预告 | ❌ |
| 开场页 | hook | 引出话题、点明核心 | ✅ |
| 概念解释页 | terminal / hero | 解释术语、定义概念 | ✅ |
| 对比页 | compare | 好 vs 坏、before vs after | ✅ |
| 清单页 | checklist | 步骤、要点、适合场景 | ✅ |
| 警告页 | warning | 反面案例、误区提醒 | ✅ |
| 收尾页 | closing | 总结、行动建议、收口 | ✅ |

### 每个场景必须包含

```python
{
    'title': '主标题\n可换行',      # 大标题，支持 \n 换行，最多2行
    'accent': '副标题',              # 标题下方的补充说明
    'caption': '底部字幕',           # 底部强调句，每页不同
    'voice': '配音内容',             # 这一页的旁白文案
    'kind': 'hook',                  # 场景类型，决定卡片样式
}
```

### 拆页原则

1. **每页只讲一个点**：不要在一个页面塞太多内容
2. **正文页共用同一骨架**：不同页面默认共享同一 scene-shell / meta-bar / title / caption / progress 结构
3. **配音节奏**：每页配音控制在 8-15 秒
4. **caption 不重复**：底部字幕每页不同，是核心金句
5. **kind 只影响局部**：`kind` 主要影响卡片内部样式，不要改整页结构

## 第二步：配音文案

### 文案要求

- 每个场景的 `voice` 字段就是配音文案
- 语速控制：使用 `RATE = '+24%'` 或根据需要调整（减慢用 `+10%`，加快用 `+35%`）
- 口语化：不要太书面，像在跟朋友聊天
- 每段结尾留 0.45 秒自然停顿

### 多音字处理

在配音文案中使用 SSML 标签：
- 多音字：`<phoneme alphabet="sapi" ph="gan 4">干</phoneme>`
- 停顿：`<break time="500ms" />`

## 第三步：排版规则

### 画布尺寸
- 固定：1080 x 1920（竖屏 9:16）

### 安全区
- 左右边距：108px
- 顶部安全区：76px（meta-bar）
- 底部安全区：224px（caption）+ 160px（progress-bar）
- 抖音遮挡区：底部约 200px，右侧约 100px

### 默认颜色主题（温暖纸感 editorial）
```
背景：#f5f4ed → #faf9f5 → #f0eee6
文字主色：#141413
文字副色：#5e5d59
强调色：#c96442
辅助强调：#d97757
页面壳：半透明暖白 + 轻边框 + 柔和阴影
```

### 字体
- 标题：Microsoft YaHei, 86px, weight 900
- 副标题：Microsoft YaHei, 44px, weight 800
- 正文/卡片：Microsoft YaHei, 28-30px, weight 400-700

### 页面骨架

所有正文页默认都保持这一套结构：

```
┌────────────────────────────┐
│  整页不透明背景             │
│  ┌──────────────────────┐  │
│  │   scene-shell        │  │
│  │  meta-bar            │  │
│  │  kicker              │  │
│  │  title               │  │
│  │  accent              │  │
│  │  card / visual       │  │
│  │  bottom-caption      │  │
│  │  progress-shell      │  │
│  └──────────────────────┘  │
└────────────────────────────┘
```

### 配图规则
- 配图页使用固定视觉容器
- 配图区域：`top: 760px`, `height: 520px`
- `object-fit: contain`
- 图片容器圆角、边框、阴影风格保持一致

## 第四步：过渡动画

### 默认原则
- 页面切换必须是 **整页作为一个整体过渡**
- 下一页进入时必须 **完整覆盖** 上一页
- 页面本体必须保持 **opaque 背景**，避免切换中露出旧页内容
- 不再默认使用内容替换式切换、clip-path 开页、shutter bar 遮挡条作为主过渡

### 页面进入动画
- 首个正文页：轻微 blur + fade 进入
- 后续正文页：从右向左整体滑入
- 进入时长：约 0.34 秒

### 页面退出动画
- 当前页整体向左推出
- 退出时长：约 0.34 秒
- 最后一页结尾再整体淡出

### 页面内元素动画
- 可以保留轻量淡入/轻位移
- 作用是辅助阅读，不是主过渡
- 不要做重 stagger，避免画面抖动和碎片感

### 当前模板关键判断标准
满足以下 3 条才算合格：
1. 换页时看到的是 **一整张新页面** 在移动
2. 新页面出现过程中 **上一页不会突然漏出来**
3. 所有页面看起来像 **同一个模板系统** 产出的连续页面

## 第五步：渲染

### 依赖
- Python: `edge-tts`（TTS配音）
- Node.js: `puppeteer-core`（截帧）
- 系统: `ffmpeg`（合成视频）
- 资产: `assets/gsap.min.js`（GSAP库，需手动下载）

### 渲染参数
- FPS: 24
- 画质: JPEG quality 92, CRF 20
- 视频编码: libx264, medium preset
- 音频编码: AAC, 192kbps

### 输出文件
- `../当前主题.mp4`: 最终视频，直接放文章文件夹根目录
- `renders/preview-frame-001.jpg`: 预览帧
- `renders/output-video.mp4`: 旧模板兼容路径，不再作为默认最终交付位置
- `renders/frames/`: 中间帧（可清理）

### 最终视频命名规则
- 文件名使用当前主题：`当前主题.mp4`
- 当前主题从文章目录名推导时，要去掉 `待-`、`待3-`、`001-` 等状态/序号前缀
- 示例：目录 `待3-Claude Code 日常更稳的 7 个动作` 的最终视频为 `Claude Code 日常更稳的 7 个动作.mp4`

## 第六步：源文件归档

视频相关源文件统一放入文章目录下的 `素材文件/`：
- `DESIGN.md`
- `*-大纲.md`
- `*-配音文件.md`

文章根目录只保留最终可直接使用的内容，例如正文和最终视频。

## 新视频制作 Checklist

- [ ] 拆分 SCENES（5-8 页）
- [ ] 确认每页只讲一个点
- [ ] 保持所有正文页使用统一页面骨架
- [ ] 写配音文案（口语化，8-15秒/页）
- [ ] 将 `DESIGN.md`、`*-大纲.md`、`*-配音文件.md` 放入 `素材文件/`
- [ ] 准备配图（从 image/2.png 开始，不含封面）
- [ ] 检查 caption 是否每页不同
- [ ] 运行 `python build_hyperframes_video.py`
- [ ] 运行 `node render_with_puppeteer.js`
- [ ] 确认最终视频已输出到文章根目录，并命名为 `当前主题.mp4`
- [ ] 验证换页是否为整页覆盖式过渡
- [ ] 验证页面风格是否全程一致
