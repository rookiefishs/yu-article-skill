# 图文输出规则

## 适用场景
- 一篇内容需要拆成更适合图文页的表达
- 节奏要快
- 每一页或每一段只说一个重点

## 默认产物
- `标题-正文.md`
- 不生成根目录 `标题-封面提示词.md`
- `配图提示词/`
  - `封面提示词.md`
  - `配图提示词.md`
  - `配图参考图.png`
  - `封面参考图.png`
- `image/`

## 内容写法
- 开头直接说结论或主题
- 开头段固定写 4 行，信息量要比 3 行更完整，但不要写成大段解释
- 开头不加标题，不加序号，直接写内容
- 从第 2 段开始，再按 `1.标题内容` 往后编号
- 开头段直接写 4 行，不加标题，不加序号
- 整篇图文默认控制在 6 到 7 个段落
- 最多不要超过 8 个段落
- 每一段尽量能单独成立
- 每一段正文尽量控制在 5 句左右，不要只写 2 到 3 句就收
- 节奏更快
- 每个点都要能看懂是在解决什么问题
- 先把一个点讲清，再进下一个点，不要一段塞太多信息
- 默认比现在再克制一点，不要解释欲太重

## 排版要求
- 图文正文中，段落与段落之间空一行分隔，不要用 --- 或其他分隔符
- 开头段直接写正文，不加标题，不加序号，固定 4 行
- 从第 2 段开始，每个段落第一行是序号加标题，格式为：1.标题内容
- 标题下方紧跟正文内容，每句一行，不要在句子之间加空行
- 每个段落内容大约 5 行，不要只写 2-3 行就收
- 段落内部不要有多余空行
- 整体要适合直接复制发布
- 不要写得太散，也不要一屏堆太多字

## 语言要求
- 句子更短
- 一段不要太长
- 多用直接表达
- 不要写成大段连续说理
- 不要说明书口吻

## 正文文件要求
- 正文默认可直接复制使用
- 不要混入 Markdown 装饰符号
- 不要出现太复杂的层级
- 不要为了整齐硬加很多标题
- 正文里不要出现 `图片文件名：NN.png` 这类映射字段
- 正文只负责可直接发布的内容，不承担图片映射说明

## 更贴近当前图文库的节奏
参照这类稿子的节奏去写：
- 开头先点题，不铺长背景，但必须写满 4 行
- 很快进入第 1 个点
- 每一段只补最关键的信息
- 一段讲完就收，不拖
- 整体读起来像一页一页往下刷，不像一篇长说明文

## 图文判断感规则
- 每一段优先先给一个判断，再补一小段解释
- 少写概念定义型开头，多写读者一看就懂的判断句
- 少写“它真正影响了什么”这类口头禅式表达，优先直接写结果、场景和动作
- 如果一句判断已经能立住，就不要再补一层抽象总结
- 能用一句短判断讲清的，就不要写成两句分析
- 比起讲全，更重要的是让读者每一段都能立刻抓住重点
- 一段里最多只保留一个因果，不要连续解释两层以上
- 要更像在告诉读者“问题在哪”“怎么做”，不要写成名词说明
- 不要频繁使用“真正xxx”“证明xxx”“值得xxx”“不是xxx，而是xxx”这类高重复辨析句式
- 不要出现“xx值得xx”“xx清楚xx”“xx更稳xx”“xx划算xx”这类空泛判断句式

## 图文和长文的区别
- 图文更强调一屏一个点
- 图文更强调节奏快、表达直
- 图文更适合把复杂内容拆成几个连续动作
- 图文默认比长文更克制，不要开头和单段写太满
- 图文更需要判断感，不要写成解释文

## 配图规则
- 默认补 `配图提示词/` 目录
- 图文场景下，封面提示词放在 `配图提示词/封面提示词.md`
- 封面提示词必须明确封面图尺寸：`图片尺寸：1536 x 2048`
- 图文场景下，所有正文配图提示词合并到 `配图提示词/配图提示词.md` 一个文件中，不再拆分成多个独立文件
- 正文配图提示词必须明确配图尺寸：`图片尺寸：2048 x 1093`
- 图文场景下，不要再额外生成或保留根目录 `标题-封面提示词.md`；如果目录里已有旧文件，默认删除旧文件
- 图文场景下，每一段都配一张图，包括开头段
- 一张配图对应一个段落的核心内容
- 正文和配图的对应关系由段落顺序维护，不要把图片文件名写回正文
- 具体格式和约束读取 `references/illustration-prompt-rules.md`

## 图文卡片两步流程

图文生产分为两步 不要混在一次交付里

### 第一步 生成基础目录和配图准备文件

当用户要求生成图文 按图文目录格式 生成封面提示词或配图提示词时 只做基础准备

- 生成 `标题-正文.md`
- 生成 `配图提示词/`
  - `封面提示词.md`
  - `配图提示词.md`
  - `封面参考图.png`
  - `配图参考图.png`
- 生成或确认 `image/`
- 不生成图文卡片 HTML
- 不生成最终卡片 PNG
- 不在正文里写图片文件名映射

这一步的目标是让用户去准备封面图和正文配图

### 第二步 配图准备好后生成图文卡片

当用户明确说配图准备好了 生成图文卡片 实现配图加文字的图文效果时 再进入卡片生成

固定产物规则

- 源码目录放在文章根目录 `图文卡片/`
  - `cards.html`
  - `render_cards.js`
- 最终发布图片放在 `image/图文卡片/`
- 不要把最终图片放到根目录 `图文卡片/output/`
- 封面图不做二次处理 直接复制原 `image/封面图.png` 到 `image/图文卡片/1.png`
- 内容页从 `2.png` 开始顺序命名 `2.png` `3.png` `4.png`
- 文件名只使用数字顺序 不使用英文说明名
- 图片尺寸固定为小红书图文卡片 `1080 x 1440`
- 文章根目录的 `图文卡片/` 是源码目录 应被项目 `.gitignore` 忽略
- `image/图文卡片/` 是最终成图目录 可以上传和发布

### 卡片内容规则

每张内容卡片必须在标题区带清楚

- 序号
- 大标题
- 详细介绍

标题区推荐结构

```text
序号
大标题
详细介绍
```

详细介绍不能只是一句很虚的概括 要解释这一页解决什么问题 或者告诉读者怎么做

### 卡片视觉规则

卡片视觉固定沿用 `claude-design-card` 的图文内容卡效果

- 尺寸 `1080 x 1440`
- 暖色纸张背景
- Georgia 或中文衬线标题
- Terracotta 强调色
- 细边框和编辑感规则线
- 主配图置于中部
- 下方保留 2 x 2 要点块或总结块
- 不使用冷色蓝灰主题
- 不使用纯白背景
- 不使用粗重卡片阴影
- 不把页面做成普通 PPT

封面页例外 封面图直接使用用户准备好的原始封面 不套卡片模板 不裁切 不加文字 不重绘

### 生成和验收

生成卡片后必须检查

- `image/图文卡片/1.png` 是否为原 `image/封面图.png` 的复制件
- `image/图文卡片/2.png` 到最后一页是否按顺序存在
- 每张内容页是否有序号 大标题 详细介绍
- 配图是否来自当前文章 `image/` 目录
- 文字是否没有溢出或遮挡
- 源码是否只在根目录 `图文卡片/` 不混入最终图片目录

## 图文照片最新规范 覆盖旧版图文卡片规则

本节优先级高于前文所有图文卡片 图文成图 目录 命名 尺寸 主题规则

### 主题

- 图文照片支持两种风格 明亮 和 暗黑
- 默认使用明亮风格
- 明亮版沿用 claude-design-card 的暖色纸张风格
- 用户明确要求暗黑 暗黑版才使用暗色背景 暖白正文 Terracotta 序号和标签 细规则线

### 尺寸

- 每一页图文照片尺寸必须一致
- 固定为 4:3 横版
- 默认导出尺寸为 `1440 x 1080`
- 不再使用旧版 `1080 x 1440` 竖版尺寸

### 目录

- 最终成图目录放在文章根目录
- 目录名固定为 `图文照片/`
- 不要放到 `image/图文卡片/`
- 不要放到 `image/图文照片/`
- 源码目录放在文章根目录
- 源码目录名固定为 `图文素材/`
- 不再使用旧源码目录名 `图文卡片/`
- `图文素材/` 必须加入项目 `.gitignore`
- `图文照片/` 是最终成图目录 不要忽略

### 命名

- 图文照片只使用数字顺序命名
- 从 `1.png` 开始
- 后续为 `2.png` `3.png` `4.png`
- 不使用英文说明名
- 不使用 `01-cover.png` 这类命名

### 封面

- 封面页为 `图文照片/1.png`
- 封面图以原 `image/封面图.png` 为主体素材
- 因为每页必须统一 4:3 尺寸 封面也要输出到 `1440 x 1080` 画布
- 不要在封面上额外套正文卡片模板
- 不要给封面新增标题说明或要点块

### 标题

- 每一页内容卡必须有 序号 大标题 详细介绍
- 首张内容页的标题序号必须从 `01` 开始 后续内容页按 `02` `03` 连续递增
- 封面页不显示内容序号 内容页不得使用 `00`
- 大标题尽量一行显示
- 如果一行放不下 优先重新润色标题 让标题更短更准
- 不要只是粗暴缩小字号到难读
- 不要让标题换成三行以上
- 详细介绍放在标题下方 解释这一页解决什么问题 或告诉读者怎么做

### 视觉

- 继续保留当前 claude-design-card 生成的图文模板结构
- 内容页布局为 标题区 主配图 要点块 页脚
- 明亮默认版使用当前 claude-design-card 暖色纸张风格
- 暗黑版使用暗色背景 暖白正文 Terracotta 序号和标签 细规则线
- 主配图必须完整可读 不要为了铺满而裁掉关键信息
- 主配图卡片必须相对整页水平居中 左右留白一致
- HTML 使用 `figure` 等语义标签承载主配图时 必须清除浏览器默认外边距 至少包含 `figure, .hero { margin: 0; }`
- 页面不要出现大面积无意义空白
- 文字不得溢出 遮挡 或压到边框

### 验收

生成后必须检查

- `图文照片/1.png` 到最后一张是否存在
- 所有图片是否都是 `1440 x 1080`
- 内容页标题是否尽量单行
- 内容页是否有 序号 大标题 详细介绍
- 默认是否为明亮风格
- `图文素材/` 是否被 `.gitignore` 忽略
- `图文照片/` 是否没有被 `.gitignore` 忽略
